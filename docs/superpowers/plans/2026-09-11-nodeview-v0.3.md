# NodeView v0.3 Scheduler + State Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn NodeView into an always-on monitoring engine with bounded scheduling, deterministic current state, threshold-based transitions, and a state API.

**Architecture:** Keep protocol checks synchronous and reusable, add an `asyncio` monitoring engine that runs them through `asyncio.to_thread()`, and keep state transition logic pure/testable. FastAPI owns engine lifecycle via lifespan while persistence remains explicitly out of scope.

**Tech Stack:** Python 3.11+, asyncio, FastAPI, Pydantic, pytest, Docker, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-11-nodeview-v0.3-design.md`

## Global Constraints

- Python 3.11+.
- Existing HTTP/TCP checker behavior remains compatible.
- Existing v0.2 YAML remains valid.
- No database/history/auth/UI in this slice.
- Run synchronous checks off the event loop.
- Default scheduler concurrency is 10.
- Default interval is 30 seconds; failure threshold 2; success threshold 1.
- UTC timezone-aware timestamps only.
- TDD for behavioral changes.
