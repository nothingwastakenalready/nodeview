# raffael v0.1 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** build the smallest useful raffael: yaml in, http checks out, readable cli.

**Architecture:** config loading, checking and cli formatting stay separate enough that none of them becomes annoying to change. results are plain dataclasses. no persistence, server or framework yet.

**Tech Stack:** python 3.11+, pyyaml, pytest, stdlib urllib, github actions

**Spec:** `docs/superpowers/specs/2026-09-08-raffael-design.md`

## Global Constraints

- public examples contain no real internal addresses or secrets.
- v0.1 only does yaml config, http checks, status/latency and cli output.
- python 3.11+.
- no dashboard, auth, database, docker, api or metrics in this version.
- production behavior gets a failing test first.

### task 1: config actually loads

**Files:**
- Create: `tests/test_config.py`
- Create: `src/raffael/config.py`
- Create: `pyproject.toml`

**Interfaces:**
- Produces: `Service(name: str, url: str, timeout: float)`
- Produces: `load_services(path: str | Path) -> list[Service]`

- [ ] write a failing test using a temporary yaml file with two services.
- [ ] run `pytest tests/test_config.py -v` and verify it fails because `raffael.config` does not exist yet.
- [ ] implement `Service` and `load_services` with clear errors for missing/invalid `services` data.
- [ ] run `pytest tests/test_config.py -v` and verify it passes.
- [ ] commit as `config works now`.

### task 2: check an endpoint

**Files:**
- Create: `tests/test_checks.py`
- Create: `src/raffael/checks.py`

**Interfaces:**
- Consumes: `Service`
- Produces: `CheckResult(name, url, status, latency_ms, http_status, error)`
- Produces: `check_http(service: Service) -> CheckResult`

- [ ] write failing tests against a local HTTP server: 200 is `up`, 503 still answered and is `down`, connection failure is `down` with an error.
- [ ] run `pytest tests/test_checks.py -v` and verify red.
- [ ] implement only the HTTP behavior needed by those tests using `urllib.request` and `time.perf_counter`.
- [ ] run the tests again and verify green.
- [ ] commit as `http checks`.
